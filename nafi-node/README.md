# پلتفرم نگار آذین فدک – نسخه Node.js / TypeScript / MySQL (پایه)

وضعیت: **هسته، منطق مالی و یک لایه HTTP قابل اجرا ساخته و تست شده است؛ پورت بقیه ماژول‌ها در حال انجام است.** مرجع رفتار، ۹۷ تست نسخه PHP است (در پوشه `../nafi`).

## نصب
1. `npm install`
2. دیتابیس خالی (MySQL 8 / MariaDB 10.6+): `CREATE DATABASE nafi CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;`
3. `cp .env.example .env` و مشخصات اتصال را وارد کنید.
4. `npm run install-app -- --email=you@example.com` : مایگریشن، مجوزها، نقش‌ها، شرکت مادر، `APP_KEY` و کاربر مالک (گذرواژه تصادفی فقط یک‌بار چاپ می‌شود).
5. تست: `npm test` (روی MySQL واقعی؛ کاربر تست باید اجازه ساخت دیتابیس‌هایی با نام `nafi_node_*` را داشته باشد) و `npm run typecheck`.

## اجرا
`npm start` (پورت پیش‌فرض ۸۰۸۰، `PORT=` قابل تنظیم). پشت HTTPS/پروکسی قرار دهید و `X-Forwarded-Proto: https` را ارسال کنید تا کوکی `Secure` شود. `MFA_REQUIRED=1` پیش‌فرض است.
صفحات فعلی: ورود + MFA، داشبورد، شرکت‌ها، برندها و دامنه‌ها، کاربران، نقش‌ها، حسابرسی، حساب من (MFA/گذرواژه)، **حسابداری** (سرفصل، دوره، ثبت/قطعی‌کردن/برگشت/حذف سند، تراز آزمایشی، دفتر معین، اتصال اعتبار و مغایرت‌گیری) و **اعتبار** (طرح، پیش‌فاکتور، درخواست، گردش وضعیت، قرارداد، فعال‌سازی، جدول اقساط، پرداخت idempotent). بازارگاه و قراردادها هنوز پورت نشده‌اند.
نمونه داده (با سرویس‌های واقعی): `npm run install-app` سپس `npx tsx scripts/demo-data.ts`.

## ویرایش، تغییر وضعیت و تاریخچه (اصل طراحی)
هر موجودیت قابل ویرایش این سه را دارد:
- **قفل خوش‌بینانه:** فرم ویرایش یک توکن نسخه (هش محتوا) دارد؛ اگر کس دیگری بین باز کردن و ذخیره، رکورد را تغییر داده باشد، ذخیره رد می‌شود و تغییرات او پاک نمی‌شود.
- **تاریخچه فیلد به فیلد:** قبل و بعد هر تغییر، کاربر، زمان و دلیل در `change_log` ثبت و در صفحه همان رکورد نمایش داده می‌شود (رمزها و کد ملی کامل هرگز وارد تاریخچه نمی‌شوند).
- **تغییر وضعیت با دلیل اجباری** و قواعد سازگار با وضعیت: شرکت (فعال/معلق/بایگانی؛ تعلیق، نشست‌های کاربران را فوراً باطل می‌کند)، برند و دامنه‌ها، کاربر (ویرایش، تغییر نقش، غیرفعال‌سازی، بازنشانی گذرواژه، رفع قفل، بازنشانی MFA فقط توسط مدیریت کل)، سرفصل حساب (کد ثابت؛ غیرفعال‌سازی فقط بدون مانده/پیش‌نویس/زیرحساب فعال)، دوره مالی (بازگشایی با دلیل)، **سند پیش‌نویس** (ویرایش کامل ردیف‌ها توسط ثبت‌کننده یا مدیر مالی؛ سند قطعی فقط با سند برگشتی)، طرح اعتباری (ویرایش تا قبل از اولین درخواست؛ بعد فقط بایگانی)، پرونده ثبت‌نام (ویرایش مشخصات بر اساس وضعیت و نقش؛ اصلاح کد ملی با دلیل و ابطال تطبیق قبلی)، مدارک (جایگزینی = نسخه جدید؛ حذف با دلیل فقط «کنار گذاشتن» است و اصل رمزنگاری‌شده و هش می‌ماند).

## آنچه پورت شده (۸۹ تست روی MariaDB واقعی)
- **لایه HTTP:** سشن سمت سرور (کوکی فقط توکن تصادفی؛ فقط SHA-256 آن در دیتابیس)، چرخش شناسه نشست پس از ورود، CSRF، سرآیندهای امنیتی (CSP بدون اسکریپت)، escape خودکار قالب‌ها (XSS)، خطاهای 500 بدون افشای جزئیات
- لایه دیتابیس MySQL، مایگریشن (اسکیما و تریگرهای تغییرناپذیری سند قطعی و نسخه قرارداد)
- رمزنگاری AES-256-GCM + نمایه کور HMAC، Argon2id، TOTP طبق RFC 6238 (با بردارهای رسمی)
- لاگ حسابرسی با زنجیره هش و **قفل ردیفی صحیح** (۴۰ نویسنده همزمان زنجیره را شاخه‌شاخه نمی‌کنند، آزموده شد)
- ورود با قفل حساب و محدودیت IP، MFA با کد بازیابی، تغییر گذرواژه، RBAC، جداسازی شرکت‌ها، سازمان (شرکت/برند/دامنه/کاربر)
- تقویم شمسی (تبدیل، ماه‌افزایی با clamp، روز کاری)، اعتبارسنجی کد ملی، قالب‌بندی ارقام فارسی
- **حسابداری دوطرفه:** سرفصل، دوره مالی، سند متوازن (عدد صحیح ریال)، تفکیک ثبت و قطعی‌کردن، شماره‌گذاری با قفل ردیفی، سند برگشتی، بستن دوره، تراز آزمایشی با جمع به والد، دفتر معین؛ سند قطعی با تریگر MySQL غیرقابل تغییر
- **ثبت‌نام و مدارک:** پرونده شخص حقیقی با رضایت‌نامه، کد ملی رمزنگاری‌شده با نمایه کور برای جست‌وجوی دقیق، بارگذاری چندبخشی (multipart) با تشخیص نوع واقعی فایل، مخزن رمزنگاری‌شده و دانلود لاگ‌شده با بررسی هش، OCR به‌عنوان پیشنهاد (مرجع نهایی کارشناس)، گردش ۱۰ وضعیتی؛ تأیید نهایی فقط پس از تطبیق کد ملی
- **اعتبار و اقساط:** طرح، پیش‌فاکتور سمت سرور، درخواست، گردش وضعیت با تفکیک وظایف، قرارداد با هش شرایط، جدول اقساط شمسی، پرداخت idempotent (شش درخواست همزمان تکراری فقط یک‌بار ثبت می‌شود)
- **اتصال اعتبار به حسابداری:** نقش‌های حساب، سند پیش‌نویس رویدادها (فعال‌سازی، دریافت قسط، تسویه پذیرنده)، مغایرت‌گیری زیرحساب با دفتر کل

## هنوز پورت نشده (به همین ترتیب)
بازارگاه و تسویه پذیرنده، قراردادها (به‌علاوه ویرایش و تاریخچه آن‌ها). (جدول‌های این ماژول‌ها در مایگریشن هستند و تریگرهایشان فعال است.) کد PHP همچنان کامل و تست‌شده است.

**نکته:** `APP_KEY` را پشتیبان بگیرید. فرمت رمزنگاری با نسخه PHP (libsodium) سازگار نیست؛ داده تولیدی PHP به‌صورت مستقیم منتقل نمی‌شود.
